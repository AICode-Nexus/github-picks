# GitHub Picks 导航与信息密度重构设计规格

日期：2026-08-04

状态：设计已确认，待实施计划

上游契约：`DailyReport v0.1.0`

替代范围：本规格替代 `2026-08-04-github-picks-web-mvp-design.md` 中关于全局导航、首页重复榜单、首屏头名和客户端交互边界的对应设计；数据契约、评分口径、详情页证据边界与静态发布方式保持不变。

## 1. 背景与实测基线

当前网站在新增 7、30、90、180 天榜和历史日报后，把同一组时间入口同时放进页头与页面内导航。首页又沿用首版“封面头名 + Top 3 + 完整综合榜 + 四个专项榜”的叠加结构，导致导航和数据都重复。

使用 `2026-08-04` 实时报表在本地浏览器实测：

- 页头与页面内同时出现“今日、7 天、30 天、90 天、180 天”，页脚又重复部分入口。
- 首页共有 20 个唯一仓库，却产生 40 次仓库卡片或榜单行展示。
- 今日头名在封面出现 1 次，在卡片和榜单中出现 6 次，共 7 次。
- 桌面页面高度约 12,350px，390px 移动端约 13,696px。
- 信源降级同时通过红色预警条和封面信源脉冲表达，状态与入口重复。
- 周期榜把周期头名放在 Hero 中，随后又在完整周期榜第 1 行重复展示；覆盖数量也在 Hero、进度条和缺失提示中反复说明。

AI HOT 只作为响应式导航的局部参考：宽屏固定导航、移动端保留高频入口。GitHub Picks 是长篇编辑型开源情报榜单，不采用资讯流卡片结构，也不在中等宽度强塞固定侧栏。

## 2. 目标

1. 全站任一视口只出现一套可见的全局时间导航。
2. 首页同一仓库只保留一个主展示节点，同时保留综合榜与四种观察标签的全部语义。
3. 同一组运行状态、信源状态或覆盖率只在一个主位置解释，其他位置只提供指向主位置的短入口。
4. 宽屏利用左侧空间增强长页导航，中等屏保持正文宽度，移动端让高频入口始终可达。
5. 保留“开源情报报纸 × 工程终端”的视觉识别，不改成通用灰色资讯流或 SaaS 仪表盘。
6. 不修改 `DailyReport`、评分算法、采集流水线、历史快照或公开证据边界。

## 3. 非目标

- 不接入新的信源或修改候选发现、补全和评分逻辑。
- 不新增搜索、收藏、登录、个性化排序或服务端 API。
- 不删除方向页、项目详情页、信源页、历史页或周期榜。
- 不以隐藏关键证据换取视觉简洁；发布分、置信度和风险仍必须分开展示。
- 不用无限滚动、虚拟列表或大型状态管理库解决只有 20 个项目的页面问题。
- 不复制 AI HOT 的图标、颜色、卡片、Logo 或信息流布局。

## 4. 方案比较

### 方案 A：唯一主榜 + 标签筛选（采用）

首页只维护一个按综合排名排序的仓库集合。前三名用重点卡片，第四至二十名用紧凑行。趋势上升、新项目、隐藏宝石和开发活跃变成同一集合上的标签与筛选条件，不再渲染四套重复卡片。

优点是数据语义完整、仓库节点唯一、筛选直接且页面显著缩短。代价是需要一个很小的 Client Component 管理当前筛选状态。

### 方案 B：后续区块排除已经出现的项目

继续保留四个专项榜，但从后续区块删除 Top 3 或综合榜中已经出现的项目。它能减少重复，却会让专项榜长度不稳定，并让用户误以为被排除项目不属于该专项榜。

### 方案 C：综合榜与专项榜放入互斥 Tab

每次只显示一套榜单，视觉高度最低，但用户切换后失去综合排名上下文，页面初始 HTML 仍包含多套重复结构，分享锚点与键盘体验也更复杂。

采用方案 A。

## 5. 设计原则

### 5.1 一个区块只回答一个问题

- 本期摘要回答“这份日报何时生成、处理了多少项目、信源是否完整”。
- 今日榜单回答“哪些项目值得关注、为什么、证据和风险如何”。
- 观察标签回答“这个项目还属于哪些观察视角”。
- 技术方向回答“可以按哪个工程领域继续浏览”。
- 读榜说明回答“分数、置信度与风险应该怎样解释”。

### 5.2 重复与概览的边界

概览可以汇总明细，但不能把同一实体的完整描述、推荐理由和三项分数再次复制。允许的概览包括信源状态计数与信源明细表、方向项目数量与方向完整榜；不允许封面头名和榜单第 1 行同时展示完整项目内容。

### 5.3 数据密度来自层级，不来自缩小字号

通过减少重复区块、限制描述行数、把相关指标放在同一行和按需展开方法明细来缩短页面。正文和关键指标字号不得低于当前可读基线，也不能依靠水平滚动容纳桌面布局。

## 6. 全局导航架构

全站只渲染一个 `SiteNavigation` 导航树，由 CSS 在三个断点改变位置和布局；不再分别维护桌面导航、移动菜单和页面内时间导航三份链接。

### 6.1 导航内容

主入口固定为：

- 今日；
- 周期：7 天、30 天、90 天、180 天；
- 历史；
- 信源。

首页在宽屏左栏额外显示本页锚点：今日榜单、技术方向、读榜说明。锚点只用于长页定位，不复制项目数据。其他页面保留面包屑和相邻内容导航，因为它们表达上下文关系而非重复全局入口。

### 6.2 宽屏：不小于 1360px

- 使用约 168–176px 的粘性左侧“情报索引”。
- 外层最大宽度扩展到约 1600px，主内容区域保持至少约 1120px 的可读宽度。
- 左栏按“日报 / 周期 / 档案 / 本页”分组，当前路由使用墨色底与荧光绿下划线。
- 页头只保留品牌和“最新日报”短状态，不再放时间链接。
- 左栏在到达页脚前保持可见，不覆盖主内容。

### 6.3 中等宽度：761–1359px

- 不显示左栏，避免长英文项目描述因正文变窄而显著增高。
- 同一个导航树变为页头下方的单行粘性导航。
- 周期入口可以横向紧凑排列，但整个页面不得产生水平溢出。

### 6.4 移动端：不大于 760px

- 同一个导航树固定在底部，四个高频入口为“今日 / 周期 / 历史 / 信源”。
- “周期”使用原生 `<details>` 打开上方弹层，列出 7、30、90、180 天；路由变化后自动关闭。
- 页面增加底部安全区内边距，最后一行内容和页脚不能被底栏遮挡。
- 键盘焦点、触控区域和屏幕阅读器名称必须完整；状态不只依赖颜色。

## 7. 首页信息架构

### 7.1 本期摘要

`DailyMasthead` 不再接收或展示 `topStory`。它只包含：

- 北京时间日期、星期、生成时间；
- 实时观测或证据回放模式；
- 评分版本；
- 候选、补全、发布的紧凑流程表达，例如 `60 → 20 → 20`；
- 信源正常、降级、离线计数和信源页入口。

存在问题信源时，本期摘要自身切换为警示状态并列出问题源的短说明。删除独立的 `source-warning` 横条和大面积 `SourcePulse`，避免同一信源状态占据两块首屏区域。

### 7.2 唯一今日榜单

首页建立一个 `DailyRanking`：

- 默认显示全部 20 个项目，并保持 `report.rankings.overall` 顺序。
- 第 1–3 名使用重点卡片，但每个项目各出现一次。
- 第 4–20 名使用紧凑榜单行。
- 每个项目节点带稳定的 `data-repository-id`，便于验证唯一性。
- 发布分、置信度和风险只在该项目节点内展示一次。
- 描述和推荐理由分别限制合理行数；完整内容仍可在项目详情页读取。

原有独立的“编辑部精选”“综合价值榜”和四个 `ranking-slices` 合并到这一条主线。

### 7.3 观察标签与筛选

从以下排名数组为每个项目派生零到多个观察标签：

- `rising` → 趋势上升；
- `newProjects` → 新项目；
- `hiddenGems` → 隐藏宝石；
- `active` → 开发活跃。

标签只表达成员关系，不改变综合榜名次。榜单标题区提供“全部”和四个标签筛选按钮：

- 默认“全部”；
- 选择标签后隐藏非成员节点，保留成员原始综合名次；
- 按钮使用 `aria-pressed` 表达状态；
- 切换不请求网络、不重新评分、不改写 URL；
- 无成员时显示明确空状态；
- 同一仓库始终只有一个 DOM 主节点。

### 7.4 技术方向

保留五个技术方向入口，但首页方向索引只展示方向名称、边界说明和入榜数量。删除每个方向的前三个项目名称，避免再次重复主榜项目。方向完整项目列表继续留在方向页。

### 7.5 读榜说明

首页保留“发布分、置信度、风险分开理解”的核心说明。八维权重放进原生 `<details>`，默认收起；用户需要时再展开。信源与安全边界保留链接，不再用三列大区块重复已在项目行表达的内容。

## 8. 其他页面去重

### 8.1 周期榜

- 删除 `period-hero__lead`，周期头名只作为榜单第 1 行出现。
- Hero 只展示周期名称、日期范围和计算口径。
- 实际日报数、日历覆盖率、入榜项目数、缺失天数合并为一个覆盖状态区。
- 缺失天数存在时在同一区域展示解释，不再增加一条重复的独立警示。
- 周期读榜方法保留一条紧凑说明。

### 8.2 历史页

- 删除页面内 `PeriodNavigation`，统一使用全局导航。
- 历史索引保留日期选择器、存档概览与日报列表，它们分别负责查询、汇总和明细，不属于重复。
- 历史日报保留日期选择器与上一期/下一期导航；前者负责任意跳转，后者负责连续阅读。

### 8.3 信源页

信源 Hero 的状态计数与信源表是“概览—明细”关系，继续保留。首页只展示一次紧凑状态摘要并链接到此页，不复制信源表内容。

### 8.4 方向页与项目详情

方向页和项目详情的数据层级已经明确，不删除关键证据。它们只接入新的全局导航框架，并继续保留面包屑与相邻方向导航。

### 8.5 页脚

删除页脚内部的今日、30 天、历史、信源导航列表。页脚只保留品牌说明、GitHub 外链和独立非官方声明，避免与持续可见的全局导航重复。

## 9. 组件与数据边界

### 9.1 新增或重构组件

- `SiteNavigation`：唯一全局导航树、路由高亮、移动周期弹层和首页锚点。
- `DailyMasthead`：重构为本期摘要，不再读取头名项目。
- `DailyRanking`：唯一项目集合和筛选状态边界。
- `RankingFilter`：筛选按钮与可访问状态，可并入 `DailyRanking` 实现。
- `TopStoryCard`：只用于综合榜前三名，支持观察标签。
- `RepositoryRow`：用于第 4–20 名，支持观察标签和更紧凑的描述层级。
- `DirectionIndex`：删除项目名摘要，只保留方向入口。
- `SiteFooter`：移除重复站内导航。

删除 `PeriodNavigation` 及其所有页面引用。`RankingSection` 继续供方向页和历史日报使用，不再用于首页生成重复切片。

### 9.2 ViewModel

新增首页专用模型：

```ts
type DailyRankingTagId = "rising" | "new" | "hidden" | "active";

interface DailyRankingItemModel extends RepositoryCardModel {
  tags: Array<{
    id: DailyRankingTagId;
    label: string;
  }>;
}
```

派生函数以 `report.rankings.overall` 为唯一主序列，再通过集合查询附加标签。任何专项排名引用了综合榜之外的仓库时，构建失败并报告数据契约错误，避免筛选后出现没有主节点的项目。

筛选只发生在浏览器展示层。服务端静态 HTML 默认包含完整综合榜，保证无 JavaScript时仍可读取全部 20 个项目。

### 9.3 客户端 JavaScript 边界

只允许两个小型 Client Component：

- `SiteNavigation` 使用 `usePathname` 更新当前路由、在导航后关闭移动周期菜单；在布局中使用 `Suspense` 提供稳定回退。
- `DailyRanking` 使用本地 `useState` 控制标签筛选。

不得增加客户端数据请求、重新评分、全局 Store、图表库或动画库。

## 10. 视觉密度规则

- 宽屏主内容宽度不得因左栏低于约 1120px。
- 主榜普通行目标高度约 140–180px，长描述与理由使用行数限制，不用极小字号。
- Top 3 可以更突出，但三张卡片总高度不得接近当前约 1000px 的独立精选区。
- 本期摘要、信源状态和处理数量合并后应在一个桌面视口内完整可见。
- 移动端不做横向榜单轮播；所有主榜项目按单列连续阅读。
- 方向和方法区使用紧凑边框、编号与原有纸张纹理，保留朱红、墨色和荧光绿语义。
- 动画继续遵守 `prefers-reduced-motion`，筛选后不使用大幅位移动画。

## 11. 可访问性与交互

- 全站仅一个 `aria-label="主导航"` 的可见全局导航。
- 当前路由使用 `aria-current="page"`；筛选使用 `aria-pressed`。
- 原生 `<details>` 的摘要具备可理解名称，展开面板不截断焦点顺序。
- 导航、筛选和项目链接全部可用键盘操作。
- 底部导航触控目标最小 44×44px，并支持 `env(safe-area-inset-bottom)`。
- 粘性页头、横向导航和底栏不得遮挡锚点目标，设置相应 `scroll-padding` 与 `scroll-margin`。
- 颜色状态同时提供文字、图标或边框，不只依赖朱红或荧光绿。

## 12. 测试与验收

### 12.1 单元与组件测试

- 首页模型对 20 个综合榜仓库生成 20 个唯一 `DailyRankingItemModel`。
- 每个观察标签与对应专项排名成员完全一致，且不改变综合名次。
- 专项排名引用综合榜外仓库时明确失败。
- 首页渲染的 `data-repository-id` 数量等于唯一值数量；`2026-08-04` fixture 为 20。
- 今日头名只出现一个项目主节点。
- 选择四种筛选时只显示对应成员，且按钮状态正确。
- 健康信源不出现警示说明，降级或离线信源只在本期摘要出现一次。
- 周期页头名只在周期榜单中出现一次。

### 12.2 浏览器测试

- 不小于 1360px：左侧情报索引可见，主内容宽度和全站无横向溢出。
- 1024px：只显示一条横向全局导航，不显示左栏或重复时间条。
- 390px：底部四入口可见，周期菜单可展开并导航，最后一行内容不被遮挡。
- 首页、周期榜、历史、方向、项目详情与信源页均只有一个可见全局导航。
- 首页筛选、详情跳转、历史日期选择和信源入口保持可用。
- 关键路由无 serious 或 critical axe 违规。

### 12.3 构建与质量门

- `pnpm lint`；
- `pnpm typecheck`；
- `pnpm test`；
- `pnpm build`；
- `git diff --check`；
- 桌面、中等宽度和移动端截图复核。

## 13. 验收标准

1. 同一视口不再同时显示页头时间导航和页面内时间导航。
2. 首页 20 个唯一项目只生成 20 个项目主节点，头名不再重复七次。
3. 四种专项观察能力通过标签筛选保留，选择后不重新计算或改变综合名次。
4. 信源降级、处理数量和日报元信息集中在一个本期摘要中。
5. 周期榜头名和覆盖说明各只有一个主表达位置。
6. 宽屏左侧空间承担导航；中等屏不因侧栏挤压正文；移动端高频入口持续可达。
7. 项目详情、方向榜、历史快照、信源明细和评分证据没有被删除或弱化。
8. 所有自动化质量门和三档浏览器验收通过。

## 14. 实施顺序

1. 先增加首页唯一模型与重复检测测试。
2. 合并首页榜单和本期摘要，删除重复区块。
3. 建立单一 `SiteNavigation` 并移除 `PeriodNavigation`。
4. 去重周期榜、方向索引和页脚。
5. 完成三档响应式样式、无障碍和浏览器回归。
6. 运行全量质量门并复核静态导出。

该顺序确保数据唯一性先由测试固定，再进行视觉布局调整；导航改造不会改变日报或评分事实。
