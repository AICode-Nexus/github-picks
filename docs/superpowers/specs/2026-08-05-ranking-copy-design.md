# GitHub Picks 榜单一键复制设计规格

日期：2026-08-05

状态：设计已确认，待规格复核

## 1. 背景与目标

GitHub Picks 的今日榜、周期榜和历史日报已经形成可公开访问的中文榜单，但用户目前需要手工整理项目名称、项目地址和榜单页面地址才能同步到群聊。

本功能提供统一的“一键复制”入口，把当前正在阅读的榜单转换成适合群聊发送的纯文本。复制结果必须满足以下目标：

1. 覆盖首页今日榜、7/30/90/180 天周期榜和每个历史日报页。
2. 首页存在标签筛选时，只复制当前筛选结果，并保持原综合名次。
3. 每个项目都包含名次、项目名、真实 GitHub 项目地址和一句核心信息。
4. 整段文本最后附当前榜单页面地址，便于群成员返回网站阅读完整内容。
5. 操作成功或失败均有明确、可访问且不造成布局跳动的反馈。

## 2. 非目标

- 不复制页面样式、图片、HTML、评分明细表或信源明细。
- 不改变日报、周期排名、历史快照、筛选或评分语义。
- 不生成短链接，不增加分享追踪参数，不接入第三方分享服务。
- 不调用系统分享面板，不针对微信、飞书或其他群聊维护平台专用格式。
- 不为方向榜、搜索结果或项目详情页增加复制入口。

## 3. 方案选择

采用“结构化纯文本生成器 + 通用客户端复制按钮”。

纯文本生成器只接收已经构建完成的榜单 ViewModel，不读取 DOM，也不重新解析 `DailyReport`。客户端按钮在点击时追加当前页面 URL 并写入系统剪贴板。这样可以让三类榜单共享文本规则，同时保留首页筛选状态这一客户端交互边界。

不采用以下方案：

- DOM 抓取：容易复制隐藏项目、辅助文字和装饰内容，页面结构变化也会破坏结果。
- 系统分享面板：桌面浏览器支持不一致，且不能稳定保证文本格式和一键复制行为。

## 4. 交互与视觉设计

### 4.1 视觉命题

复制入口是现有“报纸 × 工程终端”界面中的小型出版工具：使用当前墨色边框、纸张底色和荧光绿状态强调，不增加卡片、浮层或新的视觉主题。

### 4.2 内容与位置

- 按钮位于各榜单 `section-heading` 的右侧动作区，与 `PICKS` 数量同组。
- 按钮使用 Lucide `Copy` 图标和“复制榜单”文字，不能只依赖图标表达用途。
- 移动端动作区换行但保持在榜单内容之前，触控目标不小于 44×44px。
- 按钮宽度在“复制榜单”“已复制”“复制失败”三种状态间保持稳定，避免标题区跳动。

### 4.3 反馈

- 初始状态：复制图标 + “复制榜单”。
- 成功状态：`Check` 图标 + “已复制”，约 2 秒后恢复。
- 失败状态：`CircleAlert` 图标 + “复制失败”，同时通过 `aria-live="polite"` 暴露状态；用户可以再次点击重试。
- 写入顺序为现代 Clipboard API 优先；API 不可用或拒绝时使用页面内临时文本区域回退复制。临时节点在操作结束后立即移除。

### 4.4 动效命题

只保留现有按钮悬停颜色过渡和成功时的图标替换，不增加弹窗、Toast、位移动画或自动滚动。`prefers-reduced-motion` 下不依赖动画传达状态。

## 5. 复制文本契约

所有格式均使用纯文本和换行；项目之间空一行。不得把内部详情页地址当成项目地址。

### 5.1 今日榜

首页从当前筛选结果构建文本。选择“全部”时复制完整今日榜；选择“趋势上升”“新项目”“隐藏宝石”或“开发活跃”时，只复制该标签成员，并保留其原综合名次。

```text
GitHub Picks｜今日综合价值榜
2026-08-05｜筛选：趋势上升｜共 8 项

01 microsoft/agent-governance-toolkit
项目地址：https://github.com/microsoft/agent-governance-toolkit
推荐理由：提供 AI Agent 治理、身份与执行沙箱能力……

完整榜单：
https://aicode-nexus.github.io/github-picks/
```

每项核心信息使用该项目已有的中文推荐理由，不额外调用 AI，也不重新生成文案。

### 5.2 周期榜

周期榜复制当前周期的完整项目集合。首部包含周期名称、实际日期范围、实际日报数和项目数。每项核心信息使用已有周期统计，格式为“上榜 X/Y 日 · 平均发布分 N · 最近名次 #NN”。缺失日期仍按页面现有语义处理，不写成未上榜。

```text
GitHub Picks｜近 7 天持续价值榜
2026-07-30 至 2026-08-05｜实际日报 3 份｜共 20 项

01 owner/repository
项目地址：https://github.com/owner/repository
周期表现：上榜 3/3 日 · 平均发布分 64.8 · 最近名次 #01

完整榜单：
https://aicode-nexus.github.io/github-picks/rankings/7d/
```

### 5.3 历史日报

历史页复制所选日期保存的完整综合榜顺序。首部明确历史日期；每项使用该快照对应的中文推荐理由和 GitHub 地址。项目详情页可以展示最新公开档案，但复制内容仍来自所选历史日报的 ViewModel。

```text
GitHub Picks｜2026年08月05日综合价值榜
历史日报｜共 20 项

01 owner/repository
项目地址：https://github.com/owner/repository
推荐理由：该日保存的中文推荐理由……

完整榜单：
https://aicode-nexus.github.io/github-picks/history/2026-08-05/
```

### 5.4 页面地址规则

- 页面地址在点击时从浏览器当前 URL 获取，不在构建期硬编码生产域名。
- 保留部署 `basePath`、当前路由、查询参数和有意义的页面锚点。
- “完整榜单：”和当前页面 URL 必须是整段文本最后两行；URL 是最后一个非空内容。

## 6. 组件与数据边界

### 6.1 纯文本生成器

新增共享模块负责：

- 通用项目段落格式；
- 今日榜标题、筛选标签和推荐理由；
- 周期榜范围、覆盖事实和周期表现；
- 历史榜日期和推荐理由；
- 最终页面 URL 的追加与换行规范。

生成器接收 `DailyRankingItemModel`、`PeriodRankingModel` 或 `RepositoryCardModel` 派生的显式输入，不访问 `window`、`document` 或剪贴板，因此可在 Vitest 中精确验证。

### 6.2 客户端按钮

新增小型 Client Component `CopyRankingButton`：

- 接收不含页面 URL 的榜单正文；
- 点击时读取当前 URL、生成最终文本并执行复制；
- 管理 `idle / success / error` 三种本地状态；
- 组件卸载或连续点击时清理恢复计时器；
- 不发起网络请求，不写入本地存储，不记录用户复制内容。

### 6.3 页面接入

- `DailyRanking` 已是 Client Component，直接根据当前 `filter` 计算可见项目和复制正文；`HomePage` 传入日报日期。
- `PeriodRankingPage` 从 `PeriodRankingModel` 生成周期正文并嵌入通用按钮。
- `HistoryReportPage` 把历史日期和当日榜单复制配置传给 `RankingSection`；其他使用 `RankingSection` 的页面不显示按钮。
- `RepositoryCardModel.githubUrl` 和 `PeriodRankingItemModel.githubUrl` 是项目地址的唯一来源，内部 `href` 只用于站内详情导航。

## 7. 错误处理与兼容性

- 空榜单仍允许复制首部和当前页面地址，并显示“共 0 项”，不能抛出异常。
- Clipboard API 拒绝、不可用或抛错时自动尝试回退复制；两条路径都失败才进入错误状态。
- 回退复制不得改变当前焦点、页面滚动位置或选择区域。
- 项目描述或推荐理由中的换行压缩为空格，避免破坏项目段落边界；不修改其他合法文本。
- URL、项目名和推荐理由按纯文本处理，不插入 HTML。

## 8. 测试与验收

### 8.1 单元测试

- 今日榜“全部”和每个标签只输出对应项目，且保持原综合名次。
- 每个项目段落包含 `githubUrl`，从不输出内部 `href` 作为项目地址。
- 周期榜输出日期范围、实际日报数和周期表现，不把缺失日期视为零。
- 历史榜输出所选日期和当日推荐理由。
- 当前页面 URL 是最终文本最后一个非空内容。
- 推荐理由中的多余换行被压缩，空榜单格式稳定。

### 8.2 组件测试

- 三类榜单都显示名称明确的“复制榜单”按钮。
- Clipboard API 成功时写入完整文本并显示“已复制”。
- Clipboard API 失败时执行回退；全部失败时显示“复制失败”。
- 连续点击和组件卸载不会遗留计时器或临时 DOM 节点。
- 状态变更有可访问名称和 `aria-live` 反馈，按钮尺寸不随状态变化。

### 8.3 浏览器验收

- 首页“全部”和至少一个标签筛选分别复制正确项目集合。
- 周期榜和历史日报复制文本都包含每项 GitHub 地址，且末尾链接指向当前路由。
- GitHub Pages `basePath` 构建后，末尾链接保留完整部署路径。
- 1440px、1024px、390px 三档视口无水平溢出，按钮不遮挡标题、数量或榜单内容。
- 键盘可以聚焦并触发复制按钮；成功状态无需颜色也能识别。

### 8.4 质量门

- 先按 TDD 逐项观察新增测试失败，再实现最小代码使其通过。
- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm build`
- `git diff --check`
- Playwright 桌面和移动端复制流程与截图复核。

## 9. 验收标准

1. 今日、全部周期和历史日报均有一致的一键复制入口。
2. 首页复制内容严格跟随当前筛选，不改变综合名次。
3. 每个复制项目均包含真实 GitHub 地址和一条核心信息。
4. 当前榜单页面地址是复制文本的最后一个非空内容。
5. 成功、回退与失败路径均可验证、可重试且可访问。
6. 新入口在桌面、中等和移动视口均不造成布局溢出或跳动。
7. 排名、日报、历史快照和评分数据契约保持不变。
