# GitHub Picks Agent 教程页设计

日期：2026-08-05
状态：待用户书面复核

## 背景

GitHub Picks 已发布匿名只读 API 和可安装的 `github-picks` Agent Skill，但网站目前没有可见入口。安装命令、示例提问和故障处理只存在于 README 与运行手册中，普通访问者无法从产品页面发现这项能力。

AI HOT 的公开网站采用“主导航入口 + 独立 Agent 接入页”的模式。GitHub Picks 采用相同的信息架构，但只展示已经真实交付的 Agent Skill 与 REST API，不展示尚未提供的 MCP、RSS 或推送能力。

## 目标

- 在所有页面的主导航中增加清晰可见的“Agent”入口。
- 新增可静态导出的 `/agent/` 教程页。
- 让用户能在一个页面内完成安装、重开会话、提出第一个问题和验证结果。
- 明确匿名只读、无需密钥、保持公开榜单顺序等数据边界。
- 延续现有报纸式信息设计，在桌面和移动端都保持紧凑、可扫描和可访问。

## 不做什么

- 不新增或宣称 MCP、RSS、账号登录、私有仓库访问、自动推送或写入能力。
- 不在浏览器中直接执行安装命令。
- 不复制 AI HOT 的视觉样式、文案或多接入轨道，只借鉴可发现的信息架构。
- 不修改日报、排名、评分或公开 API 契约。

## 方案比较

### 方案 A：独立教程页与主导航入口（采用）

在主导航增加“接入 / Agent”，指向 `/agent/`。独立页面提供完整安装流程、可复制命令、示例问题、能力边界和故障排查。

优点：全站可发现、可直接分享、内容容量足够、与 AI HOT 的成熟入口一致。缺点：增加一个路由和一个小型客户端复制控件。

### 方案 B：首页内嵌教程区

在首页榜单之后加入完整教程，不新增路由。

优点：实现最少。缺点：首页已经承载日报、方向和评分说明，教程会稀释主要工作流，其他页面也难以发现。

### 方案 C：弹窗或抽屉教程

点击导航后在当前页面打开教程面板。

优点：不离开当前榜单。缺点：不能稳定分享或被搜索引擎索引，移动端内容过长，焦点管理和无脚本降级也更复杂。

## 信息架构

### 主导航

在“档案”之后增加“接入”分组和带图标的“Agent”链接：

- 桌面宽屏侧栏：显示分组标签、图标和文字。
- 中等宽度横向导航：显示图标和“Agent”。
- 移动端底部导航：与现有主入口并列，并保证周期菜单不被遮挡。
- `/agent/` 路由使用既有 `aria-current="page"` 激活规则。

首页的“本页导航”保持只指向首页区块，不混入跨页面链接。

### 教程页

页面按一次完整上手流程排列，不使用多余标签页或卡片网格：

1. **页首定位**
   - 眉题：`AGENT ACCESS / PUBLIC API V1`
   - 标题：`让 Agent 直接使用 GitHub Picks`
   - 一句话说明：安装 Skill 后，可以查询最新日报、周期榜、技术方向和已收录仓库证据。
   - 状态标签：匿名只读、无需 API Key、公开数据、Skill 已发布。

2. **三步安装**
   - `01 安装`：展示项目级安装命令，并提供带 `Copy` 图标的复制按钮。
   - `02 新开会话`：说明多数 Agent 在会话开始时扫描 Skill。
   - `03 开始提问`：给出首个验证问题。
   - 全局安装作为次级 `<details>` 内容，避免两个命令争夺主操作。

3. **装好后这样问**
   - 今天最值得关注的 5 个项目。
   - 近 30 天安全与软件供应链方向的持续项目。
   - 比较两个已收录仓库的成熟度与公开风险证据。
   - 每条示例可单独复制，但不使用会造成布局跳动的动态宽度。

4. **Agent 能做什么**
   - 最新日报。
   - 7/30/90/180 天周期榜。
   - 五个技术方向。
   - 已收录仓库详情与历史证据。

5. **数据边界与排障**
   - 只读取 GitHub Picks 固定域名的匿名只读 v1 API。
   - 不访问私有仓库，不要求 Token，不重新评分或按 Star 改序。
   - 安装后未发现 Skill：关闭旧会话并新建会话，再确认 `github-picks` 已被发现。
   - 指定日期或仓库不存在：如实返回无公开观测，不用其他数据冒充。
   - 链接到 Skill 源码、API meta 和运行手册。

## 视觉设计

视觉论点：把教程做成一张严谨的“接入说明版”，沿用现有纸张、墨色、朱红和荧光绿体系，用编号、分隔线和等宽代码形成技术秩序。

内容计划：接入主张、三步安装、示例提问、能力范围、边界与排障。

交互论点：

- 复制按钮在原位从 `复制` 切换为 `已复制`，保持固定尺寸，短暂反馈后复位。
- 键盘和鼠标悬停状态沿用站点已有高对比焦点样式。
- 仅使用现有的轻量颜色与位移过渡；`prefers-reduced-motion` 下取消非必要动画。

页面区块使用全宽分隔线和网格，不把区块堆成卡片。代码块使用深色稳定平面，与报纸式正文形成明确层级。标题大小服从现有应用页面，不新增营销式超大 Hero。

## 组件与数据流

- `app/agent/page.tsx`：静态路由与页面 metadata，渲染教程组件。
- `components/agent-tutorial-page.tsx`：服务端可渲染的教程结构和固定文案。
- `components/copy-command-button.tsx`：唯一客户端组件，接收待复制文本和无障碍标签。
- `components/site-navigation.tsx`：新增 Agent 导航项并复用现有激活逻辑。
- `styles/globals.css`：增加 `agent-*` 样式及现有断点下的响应式规则。

所有教程内容来自仓库内固定常量，不请求 API、不读取日报，也不引入新的运行时依赖。复制失败时按钮恢复可重试状态，并通过 `aria-live` 提示“复制失败，请手动选择命令”；即使 JavaScript 不可用，完整命令仍可见并能手动选择。

## 可访问性与响应式

- 页面只有一个 `h1`，各步骤和边界使用顺序正确的标题结构。
- 安装步骤使用有序列表；代码保留水平滚动，不压缩或截断命令。
- 复制按钮具有可见文字、Lucide 图标、明确 `aria-label` 和稳定点击区域。
- 桌面、平板、390 px 与 320 px 视口不产生横向页面溢出。
- 新导航项在所有断点可见、可聚焦并正确标记当前页。
- 页面通过严重和关键级 Axe 检查；复制反馈由礼貌型 live region 宣告。

## 测试

- 组件测试验证教程标题、安装命令、四类能力、三条示例问题和安全边界。
- 复制控件测试覆盖成功、失败和重复复制，不依赖真实系统剪贴板。
- 导航测试验证 `/agent/` 激活状态和链接存在。
- E2E 覆盖桌面与移动端路由、可见入口、复制交互、代码不溢出和键盘访问。
- 将 `/agent/` 加入可访问性路由集合。
- 完整运行格式化、类型检查、单元测试、静态构建和 Playwright。

## 验收标准

- 用户从任意页面最多一次点击进入 `/agent/`。
- 用户无需离开教程页即可复制可执行的项目级安装命令。
- 页面明确要求安装后新开会话，并提供至少一个可验证的真实问题。
- 页面不声称 GitHub Picks 拥有未实现的接入方式。
- 静态导出包含 `/agent/index.html`，GitHub Pages 子路径下导航与资源正常。
- 桌面与移动端均无内容遮挡、失焦、不可读文字或横向页面溢出。
