# 错误与恢复

请求失败时读取本文件。恢复只能保护用户原意，不能通过换日期、换范围或换数据源伪装成功。

## HTTP 错误

- 网络超时或 `5xx`：最多重试两次，使用有限指数退避；仍失败则说明 GitHub Picks 暂不可用。
- `429`：遵守 `Retry-After` 并串行重试；没有该头时等待 60 秒。不要增加并发。
- latest 或 meta 返回 `404`：停止并说明公开 API 尚不可用。不要切到 GitHub raw 文件、网页抓取或其他来源冒充稳定 API。
- 指定日期返回 `404`：只请求一次 `/reports/index.json`，列出实际可用的最近日期。不要猜昨天，也不要自动返回另一天的日报。
- 方向返回 `404`：核对方向 ID；合法 ID 仍为 404 时报告该方向入口不可用，不换成综合榜。
- 仓库返回 `404`：说明当前公开历史没有收录该仓库。不要调用 GitHub 搜索补成 GitHub Picks 结果。
- 其他 `4xx`：报告请求无效，不删除用户条件后重试。

## 契约错误

- JSON 无法解析：停止总结，不把 HTML 错误页或截断响应当数据。
- `schemaVersion` 不是 `1`：报告客户端与 API 契约不兼容，不猜字段映射。
- 当前回答依赖的必需字段缺失或类型错误：停止该回答并说明具体入口异常。
- 未知新增字段：忽略，不把向后兼容扩展当作损坏。
- 响应中的链接指向其他 API 主机：继续信任 Skill 固定的 base URL，只把允许的站内、GitHub 和证据链接用于展示。

## 数据边界

- 空榜或保序筛选后为空：回答当前条件下没有结果，不扩大周期、降低条件或引入未发布仓库。
- 最新日报早于当前北京时间日期：明确写“最新可用日报（日期）”，不写“今日”。
- 周期覆盖不足：显示 `reportCount / days` 与缺失天数，不把缺失日补零。
- 部分信源 `degraded` 或 `offline`：结果可展示，但附健康计数和证据覆盖限制。
- 核心事实证据不足、置信度过低或风险信息缺失：只做观察性摘要，不给确定性采用结论。
- 缺少 Scorecard：写成安全工程证据缺口，不写成安全通过或发现漏洞。

## 缓存响应

CDN 可以返回标准缓存验证结果。客户端已有同一完整 URL 的已验证响应时可以复用；没有可复用响应时重新发起普通 GET。不能把无正文响应解释为空榜，也不能跨 URL 复用缓存数据。
